## Задание — 2 семестр

Сделать воспроизводимое исследование по задачам качества PPG-сигнала и предсказания
частоты сердечных сокращений (heart rate, HR) на датасете **BUT PPG v2.0.0**, сравнить
простые базовые модели, **OpenTSLM** и **SIGMA-PPG**, проверить перенос знаний
ECG → PPG, работу моделей при малом количестве обучающих данных и внешнюю устойчивость
на датасете **GalaxyPPG**.

Итогом работы должен быть воспроизводимый проект-репозиторий. В нём должны быть скрипты
для подготовки данных, создания разбиений, обучения моделей, оценки на фиксированной
тестовой части и сохранения результатов. В репозитории не нужно хранить исходные данные,
если это запрещено условиями датасетов; вместо этого должны быть инструкции и скрипты
для их загрузки и подготовки.

В проекте нужно сохранить всё, что необходимо для повторения экспериментов: настройки
запуска, версии датасетов, начальные числа генератора случайных чисел, файлы разбиения
по испытуемым, реестры записей, обученные чекпоинты или ссылки на них, предсказания
моделей, метрики, журналы обучения и итоговые таблицы.

В README должны быть команды для полного запуска: настройка окружения, подготовка
BUT PPG, создание разбиений, обучение базовых моделей, обучение OpenTSLM, обучение или
запуск SIGMA-PPG, low-data эксперимент, подготовка GalaxyPPG и внешняя проверка на
GalaxyPPG. Также нужно добавить краткое описание структуры проекта и команду, которая
запускает оценку моделей (всех или выборочно) на фиксированной тестовой части.

### 1. Подготовка набора данных BUT PPG и базовых моделей

Нужно изучить датасет BUT PPG, подготовить воспроизводимый процесс загрузки,
предварительной обработки и разбиения данных, обучить небольшие базовые модели и
получить первые метрики. В BUT PPG v2.0.0 есть 3888 записей по 10 секунд от 50
испытуемых разного пола и возраста. PPG записан с частотой 30 Гц, ECG — 1000 Гц, данные
акселерометра (ACC) — 100 Гц. Метка качества и эталонный HR даны для каждого PPG-сигнала.
ECG используется для получения эталонного HR, но не должен попадать во входные признаки
моделей. У части записей есть ACC, поэтому это нужно отдельно учесть в обработке данных
и сравнении моделей.

### 2. Задачи для моделей на BUT PPG

**А) Качество PPG-сигнала:** бинарная классификация — подходит ли 10-секундный
PPG-сигнал для дальнейшего анализа. Для честного сравнения стоит использовать четыре
варианта входных данных:
1. только PPG на всех данных;
2. только PPG на подмножестве, где доступны ACC и нужные дополнительные данные;
3. PPG вместе с ACC на этом же подмножестве;
4. PPG вместе с ACC и дополнительными данными (пол, возраст, рост, вес, давление, место
   измерения и другие доступные поля).

**Б) Предсказание HR:** работать с сигналами, которые по разметке имеют хорошее
качество, и на них обучать модель. Отдельно сделать сквозной сценарий: сначала модель
качества определяет, подходит ли сигнал, затем HR-модель предсказывает HR только для
принятых окон. Для такого сценария указать долю принятых окон, сколько хороших сигналов
было ошибочно отброшено и сколько плохих сигналов было ошибочно принято.

ECG и эталонный HR нельзя использовать как входные признаки — только как целевое
значение для HR или для проверки разметки (иначе утечка данных).

### 3. Протокол разбиения и предварительной обработки

Окно — 10 секунд. Для PPG ожидаемый размер окна — 300 точек при 30 Гц. Для ACC нужно
подумать, использовать ли исходный сигнал 100 Гц или привести к частоте PPG.

Разбиение — строго по испытуемым, пропорция 60/20/20 (для BUT PPG: 30/10/10
испытуемых). Все записи одного испытуемого — только в одну часть. Файлы разбиения
сохранить в проекте.

Валидационную часть использовать только для подбора гиперпараметров, выбора порога и
выбора лучшего чекпоинта. Тестовая часть — фиксированная и одинаковая для всех моделей.

Зафиксировать seed, доли разбиения, сделать автоматическую проверку непересечения
испытуемых между частями. По возможности сбалансировать части по качеству сигнала,
распределению HR и месту измерения.

### 4. Минимальные базовые модели

- Признаки + Logistic Regression / XGBoost (10-секундный PPG, при необходимости + ACC →
  вектор из ~20–200 признаков).
- 1D-CNN / ResNet1D на сыром PPG (300 точек); при использовании ACC — отдельные каналы
  или отдельная ветвь сети.
- 1D-CNN / ResNet1D регрессия для HR, обученная только на сигналах хорошего качества.
- Тривиальные нижние границы: majority-class для качества; медианный HR на обучающей
  части и метод по доминирующей частоте PPG для HR.

### 5. Метрики

- Качество: **Macro-F1** (основная, выбор чекпоинта) + ROC-AUC, Accuracy,
  precision/recall/F1 по классам, матрица ошибок.
- HR: **MAE** в уд/мин (основная, выбор чекпоинта) + RMSE.
- Для всех моделей сохранять предсказания на тесте: `record_id`, `subject_id`, истинное
  значение, предсказание, вероятность класса good (задача A) или предсказанный HR
  (задача B).

### 6. Дообучение OpenTSLM

Адаптировать OpenTSLM под BUT PPG, обучить на тех же фиксированных разбиениях. Два
запуска:
1. OpenTSLM-Flamingo + Llama-3.2-3B **без** ECG-инициализации;
2. OpenTSLM-Flamingo, предварительно обученная **на ECG**-задаче.

Сравнение нужно для проверки переноса ECG → PPG.

Для задачи A зафиксировать правила разбора ответа: допустимы только `good/bad` или
`1/0`. Для задачи B — извлекать первое допустимое число в диапазоне 30–220 уд/мин.
Недопустимые ответы **не удалять молча**: сохранять исходный текст ответа, статус
разбора и долю недопустимых ответов.

ACC на первом этапе подавать как модуль ускорения (magnitude), чтобы не усложнять
архитектуру. Если останется время — отдельно проверить вариант с 3 осями ACC как
отдельными каналами/фрагментами. Выбранный способ подачи ACC зафиксировать в настройках
эксперимента.

Перед стартом обучения: сохранение чекпоинтов, возможность продолжения обучения,
отдельный скрипт оценки, подсчёт всех метрик на фиксированном тесте, выбор лучшего
чекпоинта только по валидации, сохранение настроек/предобработки/разбиения/seed вместе с
результатами.

### 7. Сравнение со SIGMA-PPG

Изучить репозиторий SIGMA-PPG, сделать предобработку датасета под неё. Дообучить
SIGMA-PPG на обучающей части BUT PPG в режиме "только PPG" — потому что предобученная
модель не оптимизирована под конкретные метки/протокол/формат окон BUT PPG. Использовать
те же train/val/test-разбиения, реестр, метки и метрики, что и для базовых моделей и
OpenTSLM. Лучший чекпоинт — только по валидации (Macro-F1 / MAE). Финальное сравнение —
только на тесте.

### 8. Внешняя проверка на GalaxyPPG

Взять модели, обученные на BUT PPG, **без дообучения** проверить предсказание HR на
GalaxyPPG. Подготовить окна (10 секунд), привести частоту/длину окна к формату каждой
модели, получить эталонный HR из ECG, посчитать MAE. **Обязательно инвертировать** сырой
PPG с Galaxy Watch (отражательный сенсор).

Считать метрики не только в целом, но и по активностям; отдельно показать, где модели
резко ухудшаются — особое внимание **walking, jogging, running** (двигательные
артефакты, см. статью GalaxyPPG).

### 9. Эксперимент с ограниченным объёмом обучающих данных

Val/test фиксированы, train искусственно уменьшается по числу испытуемых: 25%, 50%,
100%, **вложенные** подмножества (25% ⊂ 50% ⊂ 100%). Для **каждого** размера train
обучить/дообучить **как минимум**: признаковую модель, 1D-CNN/ResNet1D, **OpenTSLM без
ECG**, **OpenTSLM с ECG**, **SIGMA-PPG** — всё в режиме только PPG.

Для качества — Macro-F1 от числа обучающих испытуемых; для HR — MAE от числа обучающих
испытуемых; дополнительно таблицы ROC-AUC, Accuracy, RMSE.

Повторить для нескольких seed (минимум 3 запуска для 25% и 50%), в отчёте — среднее ±
стандартное отклонение.
