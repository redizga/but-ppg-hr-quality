## Шаг 1. E1 — данные BUT PPG (владелец: Голиков)

Это первый эпик, дающий реальные артефакты, от которых зависят все остальные (E2–E9
работают поверх `registry.csv` и файла сплита).

1.1. **Загрузка.** Реализовать `src/butppg/data/download.py` и
`scripts/prepare_but_ppg.py` (сейчас стабы) — скачивание BUT PPG v2.0.0 с PhysioNet (или
инструкция + скрипт, если автоматическая загрузка невозможна из-за лицензии). Заполнить
`download_url` в `configs/data/but_ppg.yaml`.

1.2. **Предобработка.** `src/butppg/data/preprocess.py` — нарезка окон 300 точек @30Гц
для PPG; обработка ACC согласно уже зафиксированному `acc_mode: resample_to_ppg`
(`configs/default.yaml`); извлечение эталонного HR и метки качества из исходных файлов
разметки датасета.

1.3. **Реестр.** `src/butppg/data/registry.py` — собрать `data/processed/registry.csv`:
`record_id`, `subject_id`, `quality_label`, `hr_reference`, `has_acc`, ковариаты (пол,
возраст, рост, вес, давление, место измерения — если есть в датасете), путь к файлу окна.

1.4. **Разбиение.** `src/butppg/data/splits.py` + `scripts/make_splits.py` — 60/20/20 по
`subject_id` (30/10/10 испытуемых), с балансировкой по `quality_label` +
`measurement_site` (и, если решили по Шагу 0, по бинам HR), автоматическая проверка
непересечения испытуемых между train/val/test. Сохранить
`splits/but_ppg_60_20_20.json` — этот файл коммитится в репозиторий.

1.5. **Тесты.** Добавить проверки: непересечение испытуемых, соответствие размеров окна
(300 точек), отсутствие ECG-каналов во входных признаках.

**Готово, когда:** `python scripts/prepare_but_ppg.py` и
`python scripts/make_splits.py --registry ... --out splits/but_ppg_60_20_20.json --seed 42`
реально выполняются (а не бросают `NotImplementedError`), `registry.csv` и файл сплита
существуют и проходят тесты на непересечение.

## Шаг 2. E2 — метрики, формат предсказаний, оценщик, тривиальные baseline (владелец: Будилов)

Может идти **параллельно** с E1 (не зависит от реальных данных, можно писать и тестировать
на синтетических примерах), но `evaluate.py --all` заработает по-настоящему только после
Шага 1.

2.1. `src/butppg/metrics/quality.py` — Macro-F1, ROC-AUC, Accuracy, precision/recall/F1
по классам, confusion matrix; логика подбора порога на валидации (закрывает пункт 2 из
"мелких недосказанностей").

2.2. `src/butppg/metrics/hr.py` — MAE, RMSE.

2.3. `src/butppg/metrics/predictions.py` — единый формат предсказаний:
`record_id, subject_id, y_true, y_pred, proba_good` (задача A) /
`record_id, subject_id, hr_true, hr_pred` (задача B).

2.4. Функция сквозного сценария (см. Шаг 0, п.2) — `accepted_fraction`,
`false_reject_rate` (хороший сигнал отброшен), `false_accept_rate` (плохой сигнал
принят) — как переиспользуемая функция в `evaluation/`.

2.5. Тривиальные baseline: majority-class для quality, median-HR и dominant-frequency
для HR — как отдельные "модели" под тем же CLI, что и остальные (чтобы E9 мог сравнить
их в общей таблице).

2.6. `src/butppg/evaluation/evaluate.py` + `scripts/evaluate.py` — оценка по файлам
предсказаний, флаги `--all` / конкретный файл.

**Готово, когда:** `python scripts/evaluate.py --all` считает метрики по всем
существующим файлам предсказаний (для старта — хотя бы по тривиальным baseline).

## Шаг 3. E3/E4 — базовые модели (Спринт 2, владельцы Голиков / Будилов, параллельно)

- **E3 (Голиков):** ручные признаки (~20–200, статистика + спектр) + LogReg/XGBoost.
  Реализовать все 4 варианта входов **или** реализовать только зафиксированный по Шагу 0
  набор вариантов — не молчаливо один вариант "по умолчанию".
- **E4 (Будилов):** 1D-CNN/ResNet1D для quality и для HR (отдельная регрессионная
  модель, обучаемая только на сигналах с `quality_label == good`).

**Готово, когда:** оба дают предсказания на тесте в формате из Шага 2, метрики
воспроизводимы (фиксированный seed → одинаковый результат).

## Шаг 4. E5/E6 — OpenTSLM и SIGMA-PPG (Спринты 2–3)

- **E5 (Будилов):** адаптация OpenTSLM, лоадер/промпты/парсинг ответа (строгие правила
  из задания п.6 — сохранять сырой текст, статус разбора, долю невалидных ответов), два

- **E6 (Голиков):** изучение репозитория SIGMA-PPG, предобработка под него, дообучение

**Готово, когда:** оба дают чекпоинты + предсказания на тесте в едином формате, лучший
чекпоинт выбран строго по валидации.

## Шаг 5. E7 — GalaxyPPG (Спринт 3, Будилов)

Подготовка (`prepare_galaxy_ppg.py`): окна 10с, приведение частоты/длины под каждую
модель, инверсия сырого PPG (отражательный сенсор), эталонный HR из ECG. Оценка
(`eval_external_galaxy.py`): MAE/RMSE общий и по активностям (особое внимание
walking/jogging/running) + доля окон, принятых quality-классификатором как good (без
переобучения — закрывает пункт 3 из "мелких недосказанностей").
