# Сделано: E4 (часть) — архитектура 1D-CNN / ResNet1D

Эпик E4 закреплён за Будиловым. Сделана и проверена **архитектура модели**
(`src/butppg/models/cnn1d.py`) — часть, которая не зависит от реальных данных BUT PPG:
проверяется формой тензора, а не содержимым сигнала. Цикл обучения (данные, оптимизатор,
чекпоинты) — отдельная, более крупная задача, которая реально требует E1, и она **не**
сделана сейчас — см. "Что осталось" ниже.

## Что именно по заданию (раздел 4)

> "Небольшая нейросеть на сыром PPG, например 1D-CNN или ResNet1D... подать в сеть сам
> временной ряд... Если используется ACC, можно добавить отдельные каналы или отдельную
> ветвь сети для ACC."

Т.е. одна и та же по духу модель нужна дважды: для качества (классификация) и для HR
(регрессия), с опциональным ACC.

## Что реализовано

`src/butppg/models/cnn1d.py`:
- **`ConvBlock1D`** — Conv1d→BatchNorm→ReLU (для `arch: cnn1d`).
- **`ResidualBlock1D`** — тот же блок + skip-connection (для `arch: resnet1d`,
  архитектура по умолчанию в `configs/models/cnn1d.yaml`).
- **`PPGModel`** — собирает 4 таких блока со stride=2 (уменьшение длины в 16 раз) +
  `AdaptiveAvgPool1d` на конце → один вектор признаков → `Linear` → один выходной скаляр.
  Тот же скаляр используется и для качества (как логит для `BCEWithLogitsLoss`), и для
  HR (как само значение уд/мин) — какая это задача, решает цикл обучения (функция
  потерь), не архитектура.
- **ACC — отдельная ветвь, не отдельные каналы.** Выбрал вариант "отдельная ветвь сети"
  из задания, а не склейку каналов, по конкретной причине: у ACC и PPG разная исходная
  частота (100 Гц vs 30 Гц), и решение о ресемплинге ACC — предмет отдельного выбора в
  E1 (`configs/default.yaml: acc_mode`). Если бы ветка была одна на PPG+ACC как разные
  каналы, длины пришлось бы жёстко синхронизировать. С раздельными ветками этого не
  требуется: `AdaptiveAvgPool1d` в конце каждой ветки делает её нечувствительной к длине
  входа — PPG-ветка получает 300 точек, ACC-ветка может получить хоть 1000, хоть 100,
  без изменений в коде. Проверено тестом (`test_forward_with_acc_branch_different_length`)
  на PPG-300 + ACC-1000 одновременно.
- **`build_model_from_config(cfg)`** — собирает модель прямо из
  `configs/models/cnn1d.yaml` (`arch: resnet1d`, `channels: [ppg]`); добавление `acc` в
  `channels` через CLI-оверрайд включает вторую ветвь без изменений в коде модели.

## Как проверено

`tests/test_e4_cnn1d.py` — 11 тестов на случайных тензорах:
- обе архитектуры (`cnn1d`, `resnet1d`) дают на выходе форму `(batch,)` без NaN/inf;
- ACC-ветка работает с ACC другой длины, чем PPG;
- явные ошибки при рассинхроне модели/входа (модель ждёт ACC, а его не передали, и
  наоборот) — чтобы это падало сразу с понятным сообщением, а не тихо давало неверный
  результат;
- неправильная форма PPG-входа (забыли размерность канала) — тоже понятная ошибка;
- `build_model_from_config` реально читает `configs/models/cnn1d.yaml` через
  `butppg.config.load_config` — то есть проверено не только само API модели, но и её
  стыковка с системой конфигов проекта;
- **тест на настоящем шаге обучения** — не просто forward pass, а
  `loss.backward()` + `optimizer.step()` на фиксированном батче, для обеих задач
  (`BCEWithLogitsLoss` для качества, `L1Loss` для HR): проверено, что градиенты у всех
  параметров не `None` и не нулевые, и что один шаг оптимизатора реально уменьшает loss.
  Это ловит типичный класс багов "модель существует, но не обучается" (сломанный
  граф автоград, отсоединённые тензоры и т.п.), которые forward-only тест бы не поймал.

Всего в проекте теперь **61/61 тест проходит**, `ruff check` — чисто.

## Побочный эффект: добавлена тяжёлая зависимость

Чтобы это реально проверить (не поверить на слово, что код рабочий), пришлось поставить
`torch` (CPU-сборка, ~для обучения GPU не нужен, важна только проверка форм) — ранее в
окружении его не было. Это ровно тот "тяжёлый стек", который README отдельно выносит в
`pip install -e ".[deep]"` — то есть у кого-то `torch` в окружении может не быть. Поэтому
`tests/test_e4_cnn1d.py` начинается с `pytest.importorskip("torch")` — если `torch` не
установлен, этот файл тестов **пропускается**, а не ломает весь `pytest tests/`. Основной
(`[deep]`-независимый) набор тестов как проходил, так и проходит без единой лишней
зависимости.

## Что осталось (не входит в этот кусок)

- Цикл обучения в `scripts/train_cnn.py` — DataLoader поверх реестра/витрины, оптимизатор,
  ранняя остановка, сохранение чекпоинтов, выбор лучшего чекпоинта по валидации
  (Macro-F1 для качества, MAE для HR — как уже зафиксировано в
  `configs/default.yaml: selection`), запись `RunManifest`, сохранение предсказаний в
  формате E2 (`PREDICTION_COLUMNS`) через `evaluate.py`. Всё это реально требует
  настоящих окон PPG — то есть E1. Архитектура (этот файл) уже готова быть подключённой
  сразу, как только данные появятся.
- Обучение отдельных весов для задачи A и задачи B — по заданию это разные модели
  (Quality обучается на всех окнах, HR — только на `quality_label == 1`), значит в цикле
  обучения будет **два** экземпляра `PPGModel`, не один с двумя головами — так и
  спроектировано (голова у модели одна, но экземпляров создаётся два).
